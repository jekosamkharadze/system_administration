OSI (Open Systems Interconnection) არის მოდელი, რომელიც ქსელურ კომუნიკაციას 7 ფენად ყოფს.

მისი მთავარი აზრია: როდესაც ერთი მოწყობილობა მეორესთან ურთიერთობს, სხვადასხვა ქსელური ფუნქცია სხვადასხვა ფენაზე სრულდება.

ფენები ქვემოდან ზემოთ:

1. Physical


1. Physical — ფიზიკური ფენა

ეს არის ყველაზე დაბალი ფენა.

აქ საქმე გვაქვს რეალურ სიგნალთან და ფიზიკურ გადაცემასთან — როგორ გადადის 0 და 1 კაბელით, რადიოსიგნალით ან ოპტიკური ბოჭკოთი.

მაგალითად:

Ethernet კაბელი
ოპტიკური ბოჭკო
Wi-Fi რადიოსიგნალი
ელექტრული/ოპტიკური სიგნალი
ქსელის ფიზიკური კონექტორები

მთავარი: აქ ჯერ არ გვაინტერესებს IP ან MAC — უბრალოდ მონაცემის ბიტების სახით ფიზიკური გადაცემაა.

Physical = სიგნალი და ფიზიკური გადაცემა

2. Data Link — მონაცემთა არხის ფენა

აქ უკვე ჩნდება MAC Address და Ethernet Frame.

ამ ფენაზე ხდება მონაცემების Frame-ებად ორგანიზება და ლოკალურ ქსელში მათი გადაცემა.

აქ მუშაობენ:

MAC Address
Ethernet
Switch

მაგალითად, Switch იღებს Ethernet Frame-ს და Destination MAC-ის მიხედვით განსაზღვრავს, რომელ პორტზე უნდა გააგზავნოს.

Data Link = MAC + Frame + Switch

3. Network — ქსელური ფენა

აქ მთავარი ხდება IP Address.

ამ ფენის მთავარი ამოცანაა სხვადასხვა ქსელებს შორის მონაცემების გადაადგილება და შესაბამისი მიმართულების არჩევა.

აქ მუშაობს:

IPv4 / IPv6
Router
IP Address

მაგალითად:

PC → Router → სხვა ქსელი → Server

Router Destination IP-ის მიხედვით განსაზღვრავს, სად უნდა წავიდეს პაკეტი.

Network = IP + Routing + Router

4. Transport — სატრანსპორტო ფენა

ეს ფენა პასუხისმგებელია მოწყობილობებს შორის მონაცემების ტრანსპორტირებაზე.


მაგალითად:

192.168.1.10:443

აქ 443 არის პორტი, რომელიც ეხმარება სისტემას განსაზღვროს, რომელ ქსელურ სერვისს უნდა მიეწოდოს მონაცემი.

TCP-ს შეუძლია უზრუნველყოს საიმედო მიწოდება, ხოლო UDP უფრო მსუბუქი და ნაკლები კონტროლის მქონე გადაცემაა.

Transport = TCP/UDP + Port

5. Session — სესიის ფენა

ეს ფენა დაკავშირებულია კომუნიკაციის სესიის მართვასთან — კავშირის/სესიის დაწყებასთან, შენარჩუნებასთან და დასრულებასთან.

მაგალითად, როდესაც ორ სისტემას შორის გარკვეული კომუნიკაციის სესია მიმდინარეობს, ამ ფენასთან დაკავშირებული ფუნქციები ეხმარება ამ კომუნიკაციის ორგანიზებას.

პრაქტიკაში თანამედროვე ქსელებში Session-ის ფუნქციები ხშირად სხვა ფენებთან არის გაერთიანებული, ამიტომ სისტემურ ადმინისტრირებაში მას ცალკე მოწყობილობად ან კონკრეტულ პროტოკოლად ხშირად ვერ შეხვდები.

Session = კომუნიკაციის სესიის მართვა

6. Presentation — წარმოდგენის ფენა

ეს ფენა დაკავშირებულია მონაცემების ფორმატთან და წარმოდგენასთან.

მისი იდეაა, რომ სხვადასხვა სისტემამ მონაცემები ისეთი ფორმით მიიღოს, რომლის გაგებაც შეუძლია.

აქ შეიძლება დაკავშირებული იყოს:

მონაცემთა ფორმატირება
Encoding/Decoding
Compression
Encryption/Decryption

მაგალითად, მონაცემის დაშიფვრა ან მისი კონკრეტულ ფორმატში წარმოდგენა შეიძლება ამ ფენის ფუნქციად განვიხილოთ.

Presentation = მონაცემის ფორმატი, დაშიფვრა, შეკუმშვა

7. Application — აპლიკაციის ფენა

ეს არის OSI-ის ყველაზე ზედა ფენა და ყველაზე ახლოსაა მომხმარებლის აპლიკაციებთან და ქსელურ სერვისებთან.

აქ გვხვდება ისეთი პროტოკოლები, როგორიცაა:

HTTP / HTTPS — ვებგვერდები
DNS — დომენის IP-ად გადაყვანა
FTP — ფაილების გადაცემა
SMTP — ელფოსტის გაგზავნა
SSH — დისტანციური მართვა

მაგალითად, როდესაც ბრაუზერში შედიხარ ვებსაიტზე, HTTP/HTTPS Application Layer-ის პროტოკოლებია.

Application = ქსელური სერვისები და აპლიკაციასთან დაკავშირებული პროტოკოლები



7. Application   → HTTP, DNS, SSH
6. Presentation  → მონაცემის ფორმატი/დაშიფვრა
5. Session       → სესიის მართვა
4. Transport     → TCP, UDP, Port
3. Network       → IP, Router
2. Data Link     → MAC, Ethernet, Switch
1. Physical      → კაბელი, სიგნალი, Wi-Fi
