Proxy (Proxy Server) არის შუამავალი სერვერი, რომელიც მომხმარებლის მოწყობილობასა და დანიშნულების სერვერს შორის დგას. როდესაც მომხმარებელი რომელიმე რესურსთან დაკავშირებას ცდილობს, მოთხოვნა შეიძლება პირდაპირ დანიშნულების სერვერთან არ წავიდეს. ამის ნაცვლად, მოთხოვნა ჯერ Proxy Server-ს მიეწოდება, ხოლო Proxy შემდეგ აგზავნის მას დანიშნულების სერვერთან.

მაგალითად, ჩვეულებრივი კავშირის დროს გვაქვს:

კომპიუტერი → Internet → Website

Proxy-ის გამოყენებისას კი კავშირი ხდება:

კომპიუტერი → Proxy Server → Website

ამ შემთხვევაში Proxy ასრულებს შუამავლის როლს. კომპიუტერი ეუბნება Proxy-ს, რომელ რესურსთან სურს დაკავშირება, Proxy კი ამ მოთხოვნას შესაბამის სერვერთან აგზავნის და მიღებულ პასუხს ისევ კომპიუტერს უბრუნებს.

მაგალითად, თუ ბრაუზერში შევდივართ example.com-ზე და ბრაუზერი Proxy-ს იყენებს, მოთხოვნა შეიძლება ასეთი გზით წავიდეს:

Browser → Proxy → example.com

შემდეგ პასუხი ბრუნდება:

example.com → Proxy → Browser

Proxy-ის ერთ-ერთი მნიშვნელოვანი გამოყენება არის Access Control, ანუ წვდომის კონტროლი. ორგანიზაციაში შეიძლება არსებობდეს Proxy Server, რომლის საშუალებითაც ადმინისტრატორი განსაზღვრავს, რომელ ვებსაიტებზე ან რესურსებზე შეიძლება მომხმარებლების წვდომა. მაგალითად, კომპანიამ შეიძლება გარკვეული კატეგორიის ვებსაიტებზე წვდომა შეზღუდოს.

Proxy ასევე შეიძლება გამოიყენებოდეს Caching-ისთვის. Proxy Server-ს შეუძლია გარკვეული რესურსების დროებით შენახვა. თუ იგივე რესურსი სხვა მომხმარებელსაც დასჭირდება და ის Proxy-ის cache-ში არსებობს, Proxy-ს შეუძლია არსებული ასლის გამოყენება და დანიშნულების სერვერთან ხელახლა დაკავშირება ყოველთვის არ დასჭირდეს. ეს განსაკუთრებით სასარგებლო იყო და არის ისეთ გარემოებებში, სადაც ერთი და იგივე რესურსს ბევრი მომხმარებელი ითხოვს.

Proxy-ს შეუძლია ასევე შეასრულოს Logging და Monitoring ფუნქცია. მაგალითად, ორგანიზაციის ქსელში Proxy-ს შეუძლია დააფიქსიროს, რომელი მოთხოვნები იგზავნება ინტერნეტში. ამ ინფორმაციის გამოყენებით ქსელის ადმინისტრატორს შეუძლია ქსელის გამოყენების კონტროლი და პრობლემების აღმოჩენა.

Proxy-ს რამდენიმე ტიპი არსებობს. სისტემურ ადმინისტრირებაში განსაკუთრებით მნიშვნელოვანია Forward Proxy და Reverse Proxy.

Forward Proxy არის ის შემთხვევა, როდესაც Proxy მომხმარებლის ან შიდა ქსელის სახელით მოქმედებს. მაგალითად, კომპანიის კომპიუტერები ინტერნეტში გასასვლელად იყენებენ ერთ Proxy Server-ს:

კომპიუტერები → Forward Proxy → Internet

აქ Proxy დგას მომხმარებლებსა და ინტერნეტს შორის.

Reverse Proxy საპირისპირო მიმართულებით მუშაობს. ის დგას ინტერნეტიდან შემომავალი მომხმარებლების წინ და მათ მოთხოვნებს შიდა სერვერებზე ანაწილებს:

Internet → Reverse Proxy → Web Server

მაგალითად, კომპანიას შეიძლება ჰქონდეს ვებსაიტის რამდენიმე backend სერვერი. მომხმარებელი უკავშირდება Reverse Proxy-ს, ხოლო Reverse Proxy მოთხოვნას შესაბამის backend სერვერს გადასცემს. Reverse Proxy ხშირად გამოიყენება დატვირთვის გადანაწილებისთვის, TLS termination-ისთვის, უსაფრთხოების დამატებითი ფენისთვის და ვებ-სერვერების წინ განთავსებისთვის.

ამიტომ Forward Proxy ძირითადად იცავს ან მართავს კლიენტების მხრიდან გამავალ მოთხოვნებს, ხოლო Reverse Proxy სერვერების წინ დგას და შემომავალ მოთხოვნებს იღებს.

Proxy და VPN ერთმანეთის მსგავსი ჩანს, რადგან ორივე შეიძლება მომხმარებელსა და ინტერნეტს შორის შუამავალი იყოს, მაგრამ ისინი ერთი და იგივე ტექნოლოგია არ არის. Proxy ხშირად კონკრეტული აპლიკაციის ან კონკრეტული ტიპის ტრაფიკისთვის გამოიყენება, ხოლო VPN ქმნის დაცულ VPN Tunnel-ს მოწყობილობასა და VPN სერვერს შორის და ჩვეულებრივ უფრო ფართო ქსელურ ტრაფიკს ატარებს ამ გვირაბში.

მნიშვნელოვანია ასევე გვახსოვდეს, რომ Proxy თავისთავად არ ნიშნავს Encryption-ს. თუ კონკრეტული Proxy დაშიფრულ კავშირს არ იყენებს, Proxy-სა და მომხმარებელს შორის მონაცემები ავტომატურად დაშიფრული არ ხდება. მაგალითად, HTTPS თავად უზრუნველყოფს ვებსაიტთან დაშიფრულ კავშირს, ხოლო Proxy ამ კავშირის შუამავალი შეიძლება იყოს.

საბოლოოდ, Proxy შეგვიძლია წარმოვიდგინოთ როგორც შუამავალი, რომელიც იღებს კლიენტის მოთხოვნას, საჭიროების შემთხვევაში ამოწმებს ან ამუშავებს მას და შემდეგ აგზავნის დანიშნულების სერვერთან. Forward Proxy გამოიყენება კლიენტების მხარეს, ხოლო Reverse Proxy — სერვერების მხარეს.

მარტივი სქემით:

Forward Proxy:
Client → Proxy → Internet

Reverse Proxy:
Internet → Reverse Proxy → Server

ამიტომ სისტემურ ადმინისტრირებაში Proxy-ს ცოდნა მნიშვნელოვანია, რადგან ის შეიძლება გამოიყენებოდეს წვდომის კონტროლისთვის, მონიტორინგისთვის, caching-ისთვის, უსაფრთხოების დამატებითი ფენისთვის და სერვერებზე შემომავალი ტრაფიკის სამართავად.
