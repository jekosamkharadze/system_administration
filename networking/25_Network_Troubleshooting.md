Network Troubleshooting არის ქსელში არსებული პრობლემის მოძებნისა და მისი მიზეზის დადგენის პროცესი. System Administration-ში ხშირად გვხვდება შემთხვევა, როდესაც მომხმარებელი ამბობს, რომ ინტერნეტი არ მუშაობს, ვებგვერდი არ იხსნება ან კომპიუტერი ქსელს ვერ უკავშირდება. ასეთ დროს ადმინისტრატორმა პრობლემა ეტაპობრივად უნდა შეამოწმოს და დაადგინოს, კონკრეტულად რომელ ნაწილში წყდება კავშირი.

ქსელის დიაგნოსტიკისთვის Windows-ში გამოიყენება რამდენიმე მნიშვნელოვანი ბრძანება, მათ შორის ipconfig, ping, tracert, nslookup, arp, route და netstat. თითოეულ მათგანს თავისი დანიშნულება აქვს.

პირველ რიგში ხშირად გამოიყენება ipconfig, რომელიც კომპიუტერის ქსელურ კონფიგურაციას გვაჩვენებს. მაგალითად, ipconfig-ის საშუალებით შეგვიძლია ვნახოთ კომპიუტერის IPv4 მისამართი, Subnet Mask და Default Gateway. უფრო დეტალური ინფორმაციის სანახავად გამოიყენება ipconfig /all, რომელიც დამატებით გვიჩვენებს Network Adapter-ის, DHCP-ისა და DNS-ის შესახებ ინფორმაციას. მაგალითად, თუ კომპიუტერს აქვს IP 192.168.1.10, Subnet Mask 255.255.255.0 და Default Gateway 192.168.1.1, შეგვიძლია დავინახოთ, რომ კომპიუტერი სწორად არის ჩართული ლოკალურ ქსელში და Gateway-დ 192.168.1.1 იყენებს.

შემდეგ შეიძლება გამოვიყენოთ ping. ეს ბრძანება ამოწმებს, შეუძლია თუ არა კომპიუტერს კონკრეტულ IP მისამართთან ან hostname-თან დაკავშირება. მაგალითად, ping 192.168.1.1 ამოწმებს კომპიუტერსა და Default Gateway-ს შორის კავშირს. თუ პასუხი მოდის, მაგალითად Reply from 192.168.1.1, ეს ნიშნავს, რომ ლოკალურ ქსელში Gateway-მდე კავშირი არსებობს. შემდეგ შეგვიძლია შევამოწმოთ ინტერნეტთან IP კავშირი ბრძანებით ping 8.8.8.8. თუ აქაც პასუხი მოდის, კომპიუტერს ინტერნეტთან IP დონეზე კავშირი აქვს.

შემდეგ შეიძლება შემოწმდეს hostname, მაგალითად ping google.com. ეს უკვე დამატებით ამოწმებს DNS-ის მუშაობასაც, რადგან google.com ჯერ IP მისამართად უნდა გადაიქცეს. თუ 8.8.8.8-ზე Ping მუშაობს, მაგრამ google.com-ზე არა, შესაძლებელია პრობლემა DNS-ის კონფიგურაციასთან იყოს დაკავშირებული.

DNS-ის ცალკე შესამოწმებლად გამოიყენება nslookup. მაგალითად, nslookup google.com გვიჩვენებს, რომელ IP მისამართს აბრუნებს DNS სერვერი google.com-ისთვის. ამ ბრძანებით შეგვიძლია გავარკვიოთ, მუშაობს თუ არა DNS Resolution, ანუ დომენის სახელის IP მისამართად გადაქცევა.

ქსელის პრობლემის უფრო დეტალურად გასარკვევად გამოიყენება tracert. მაგალითად, tracert google.com გვიჩვენებს, რა ქსელური გზით მიდის პაკეტი დანიშნულებამდე. გზაზე პაკეტმა შეიძლება რამდენიმე Router გაიაროს და თითოეული ასეთი შუალედური წერტილი Hop-ად ითვლება. ამიტომ ping ძირითადად გვიჩვენებს, გვაქვს თუ არა კავშირი კონკრეტულ მისამართამდე, ხოლო tracert გვეხმარება დავინახოთ, რა გზას გადის ტრაფიკი და დაახლოებით რომელ მონაკვეთში შეიძლება წარმოიქმნას პრობლემა.

ლოკალურ ქსელში IP და MAC მისამართების შესაბამისობის სანახავად გამოიყენება arp -a. ARP-ის საშუალებით კომპიუტერი IPv4 მისამართს შესაბამის MAC მისამართთან აკავშირებს. მაგალითად, თუ სიაში ჩანს 192.168.1.1 და მის გვერდით კონკრეტული MAC Address, ეს ნიშნავს, რომ კომპიუტერმა Gateway-ის IP-ს შესაბამისი MAC მისამართი იცის. arp განსაკუთრებით გამოსადეგია ლოკალურ ქსელში ARP-თან დაკავშირებული პრობლემების დიაგნოსტიკის დროს.

კომპიუტერის Routing Table-ის სანახავად გამოიყენება route print. Routing Table შეიცავს ინფორმაციას იმის შესახებ, თუ რომელი ქსელისკენ რა მიმართულებით უნდა გაიგზავნოს ტრაფიკი. მაგალითად, თუ ცხრილში ჩანს 0.0.0.0/0 ან მისი შესაბამისი ფორმა 0.0.0.0 0.0.0.0, ეს არის Default Route, რომლის საშუალებითაც კომპიუტერი იმ ქსელებისკენ აგზავნის ტრაფიკს, რომლებისთვისაც უფრო კონკრეტული მარშრუტი არ აქვს.

ქსელური კავშირებისა და პორტების სანახავად გამოიყენება netstat. მაგალითად, netstat -ano გვიჩვენებს აქტიურ კავშირებს, Local Address-ს, Local Port-ს, Remote Address-ს, პორტის მდგომარეობას და შესაბამის Process ID-ს (PID). ეს შეიძლება დაგვეხმაროს იმის გარკვევაში, რომელ ქსელურ კავშირებს იყენებს კომპიუტერი და რომელი პროცესია კონკრეტულ კავშირთან დაკავშირებული.

ქსელის პრობლემის დიაგნოსტიკისას სასურველია შემოწმება ეტაპობრივად განხორციელდეს. მაგალითად, თუ მომხმარებელი ამბობს, რომ ინტერნეტი არ მუშაობს, პირველ რიგში ipconfig-ით ვამოწმებთ, მიიღო თუ არა კომპიუტერმა სწორი IP მისამართი, Subnet Mask და Default Gateway. შემდეგ ping 192.168.1.1-ით ვამოწმებთ ლოკალურ ქსელთან და Gateway-სთან კავშირს. თუ Gateway ხელმისაწვდომია, შემდეგ ping 8.8.8.8-ით ვამოწმებთ ინტერნეტთან IP კავშირს. თუ IP მისამართთან კავშირი მუშაობს, მაგრამ დომენის სახელთან, მაგალითად google.com-თან, პრობლემა გვაქვს, nslookup-ით ვამოწმებთ DNS-ს. თუ საჭიროა იმის გარკვევა, სად წყდება გზა დანიშნულებამდე, ვიყენებთ tracert-ს.

ამგვარად, თითოეული ბრძანება პრობლემის სხვადასხვა ნაწილს ამოწმებს. ipconfig გვიჩვენებს კომპიუტერის ქსელურ კონფიგურაციას, ping ამოწმებს კავშირს კონკრეტულ მისამართამდე, tracert აჩვენებს პაკეტის გზას, nslookup ამოწმებს DNS Resolution-ს, arp გვიჩვენებს IP-სა და MAC-ის შესაბამისობებს, route გვიჩვენებს Routing Table-ს, ხოლო netstat გვაძლევს ინფორმაციას აქტიური ქსელური კავშირებისა და პორტების შესახებ.

მთავარი იდეა არის ის, რომ Network Troubleshooting-ში პრობლემას შემთხვევით არ ვეძებთ. კავშირს ეტაპობრივად ვამოწმებთ და თითოეული ტესტის შედეგით ვიკვლევთ შესაძლო მიზეზების რაოდენობას. მაგალითად, თუ Gateway-ზე Ping ვერ გადის, პრობლემა შეიძლება ლოკალურ ქსელში, Wi-Fi-ში, კაბელში, Network Adapter-ში ან Gateway-ის მხარეს იყოს. თუ Gateway მუშაობს, მაგრამ 8.8.8.8 არ პასუხობს, პრობლემა შეიძლება Router-ის, ISP-ის ან ინტერნეტთან კავშირის მხარეს იყოს. ხოლო თუ 8.8.8.8 მუშაობს და google.com არა, ყურადღება უკვე DNS-ის მიმართულებით უნდა გადავიტანოთ.
