წარმოიდგინეთ, რომ კომპანიაში ყველა კომპიუტერი, სერვერი და სხვა მოწყობილობა ერთ მთავარ Switch-ზეა დამოკიდებული. ეს Switch ძალიან მნიშვნელოვანია, რადგან თუ ის გაფუჭდა ან ელექტროენერგია გაეთიშა, მასთან დაკავშირებული მოწყობილობები ქსელთან კავშირს დაკარგავენ. ასეთ სიტუაციაში მთელი ქსელის მუშაობა შეიძლება შეწყდეს. სწორედ ასეთი პრობლემის თავიდან ასაცილებლად გამოიყენება Network Redundancy, ანუ ქსელის რეზერვირება.

Network Redundancy ნიშნავს, რომ ქსელში მნიშვნელოვანი მოწყობილობისთვის ან კავშირისთვის დამატებით ალტერნატიულ გზას ვქმნით. მთავარი კავშირის ან მოწყობილობის გათიშვის შემთხვევაში ქსელს შეუძლია სხვა გზით გააგრძელოს მუშაობა. იდეა მარტივია: ერთი კავშირის ან მოწყობილობის დაზიანება არ უნდა ნიშნავდეს მთელი ქსელის გაჩერებას.

მაგალითად, კომპანიას შეიძლება ჰქონდეს ორი Switch. კომპიუტერები დაკავშირებულია პირველ Switch-თან, ხოლო მეორე Switch დამატებით რეზერვად არის გამოყენებული. თუ პირველ Switch-ს პრობლემა შეექმნა, წინასწარ დაგეგმილი ქსელური არქიტექტურისა და შესაბამისი პროტოკოლების დახმარებით შესაძლებელია ტრაფიკის სხვა გზაზე გადართვა.

Redundancy შეიძლება მხოლოდ მოწყობილობებს არ ეხებოდეს. მაგალითად, ორ Switch-ს შორის შეიძლება გვქონდეს ორი სხვადასხვა ფიზიკური კავშირი. თუ ერთი Ethernet კაბელი დაზიანდა, მეორე კაბელი შეიძლება დარჩეს აქტიური. სწორედ ამიტომ Link Aggregation/LACP-იც შეიძლება გარკვეულ შემთხვევებში კავშირის რეზერვირებას დაეხმაროს.

ასევე შეიძლება გვქონდეს ორი Router ან ორი Internet კავშირი. მაგალითად, კომპანიას შეიძლება ჰქონდეს ძირითადი ISP და დამატებითი ISP. თუ პირველი Internet კავშირი გაითიშა, ქსელს შეუძლია მეორე კავშირის გამოყენება. ამ შემთხვევაში ერთი პროვაიდერის პრობლემა მთლიანად არ აჩერებს კომპანიის ინტერნეტთან წვდომას.

თუმცა ქსელში დამატებითი კავშირების უბრალოდ შეერთება ყოველთვის სწორი გამოსავალი არ არის. მაგალითად, თუ ორი Switch ერთმანეთთან რამდენიმე კაბელით პირდაპირ დავაკავშირეთ და შესაბამისი მექანიზმი არ გვაქვს, შეიძლება შეიქმნას Network Loop. ასეთმა Loop-მა Layer 2 ქსელში სერიოზული პრობლემა შეიძლება გამოიწვიოს. ამიტომ რეზერვირებული კავშირების სამართავად გამოიყენება შესაბამისი ტექნოლოგიები და პროტოკოლები, მაგალითად STP (Spanning Tree Protocol), რომელიც ზედმეტი გზების გამო წარმოქმნილი Loop-ებისგან ქსელის დაცვაში გვეხმარება.

Network Redundancy განსაკუთრებით მნიშვნელოვანია ისეთ გარემოში, სადაც ქსელის გათიშვა სერიოზულ პრობლემას გამოიწვევს. მაგალითად, კომპანიებში, Data Center-ებში, სერვერების ინფრასტრუქტურაში, ბანკებში და სხვა მნიშვნელოვან სისტემებში ხშირად გამოიყენება რეზერვირებული Switch-ები, Router-ები, კავშირები, კვების წყაროები და Internet კავშირები.

ამრიგად, Network Redundancy-ის მთავარი მიზანია Single Point of Failure-ის შემცირება. Single Point of Failure არის ისეთი ერთი კომპონენტი, რომლის გაფუჭებამაც შეიძლება მთელი სისტემის მუშაობა შეაჩეროს. თუ ასეთი კომპონენტისთვის ალტერნატიული გზა ან მოწყობილობა გვაქვს, სისტემის გამძლეობა იზრდება და ერთი კომპონენტის დაზიანება ავტომატურად არ იწვევს მთლიანად ქსელის გათიშვას.

მოკლედ, Network Redundancy ნიშნავს ქსელში დამატებითი კავშირების ან მოწყობილობების არსებობას, რათა ძირითადი კომპონენტის გათიშვის შემთხვევაში ქსელმა ალტერნატიული გზით გააგრძელოს მუშაობა.
