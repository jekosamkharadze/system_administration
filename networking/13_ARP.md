ARP (Address Resolution Protocol) არის პროტოკოლი, რომელიც ლოკალურ ქსელში გამოიყენება იმის გასაგებად, რომელ MAC Address-ს ეკუთვნის კონკრეტული IP Address.

ანუ:

IP Address → MAC Address

რატომ არის საჭირო ARP?

კომპიუტერმა შეიძლება იცოდეს, რომ მონაცემი უნდა გაუგზავნოს:

192.168.1.20

მაგრამ Ethernet ქსელში მონაცემის ჩარჩოს (Frame) გასაგზავნად საჭიროა მიმღების MAC Address.

ამიტომ კომპიუტერი ქსელში კითხულობს:

„ვის აქვს IP 192.168.1.20? მითხარი შენი MAC Address.“

მოწყობილობა, რომელსაც ეს IP აქვს, პასუხობს:

„ეს IP ჩემია და ჩემი MAC არის AA:BB:CC:11:22:33.“

ამის შემდეგ კომპიუტერს შეუძლია მონაცემის გაგზავნა შესაბამის MAC მისამართზე.

ARP-ის მარტივი მაგალითი

დავუშვათ, ქსელში გვაქვს:

PC 1
IP: 192.168.1.10
MAC: AA:AA:AA:AA:AA:AA

PC 2
IP: 192.168.1.20
MAC: BB:BB:BB:BB:BB:BB

PC 1-ს უნდა გაუგზავნოს მონაცემი PC 2-ს.

მას იცის:

192.168.1.20

მაგრამ ჯერ არ იცის მისი MAC.

ამიტომ აგზავნის ARP Request-ს:

ვინ არის 192.168.1.20?

PC 2 პასუხობს ARP Reply-ით:

192.168.1.20 არის
BB:BB:BB:BB:BB:BB

ახლა PC 1-ს უკვე აქვს IP-სა და MAC-ის შესაბამისობა და შეუძლია მონაცემის გაგზავნა.


ARP Cache

კომპიუტერი ყოველ ჯერზე თავიდან რომ არ კითხულობდეს MAC მისამართს, მიღებულ ინფორმაციას დროებით ინახავს ARP Cache-ში.

მაგალითად:

192.168.1.20 → BB:BB:BB:BB:BB:BB

შემდეგ იგივე მოწყობილობასთან კომუნიკაციისას შეუძლია ეს ინფორმაცია პირდაპირ გამოიყენოს.

ARP-ის მთავარი იდეა

IP მისამართი გამოიყენება იმის დასადგენად, რომელ მოწყობილობასთან გვინდა კომუნიკაცია, ხოლო MAC მისამართი საჭიროა ლოკალურ ქსელში Ethernet Frame-ის კონკრეტულ ქსელურ ინტერფეისამდე მისატანად.

ამიტომ დაიმახსოვრე:

ARP = IP Address-ის მიხედვით შესაბამისი MAC Address-ის პოვნა.

შენიშვნა: ARP ძირითადად IPv4 ქსელებისთვის გამოიყენება. IPv6-ში ამ ფუნქციას Neighbor Discovery Protocol (NDP) ასრულებს.
