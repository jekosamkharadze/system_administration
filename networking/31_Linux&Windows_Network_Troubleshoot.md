ქსელის პრობლემის აღმოჩენისას სისტემური ადმინისტრატორი სხვადასხვა ბრძანებას იყენებს იმის გასარკვევად, კონკრეტულად სად არის პრობლემა. Linux-სა და Windows-ს განსხვავებული ბრძანებები აქვს, მაგრამ მათი მიზნები ხშირად ერთმანეთის მსგავსია. ამიტომ მნიშვნელოვანია არა მხოლოდ ბრძანების დამახსოვრება, არამედ იმის გაგება, რას ამოწმებს ეს ბრძანება.

პირველი, რაც უნდა შევამოწმოთ, არის მოწყობილობის ქსელური კონფიგურაცია. Windows-ში ამისთვის გამოიყენება ipconfig, ხოლო Linux-ში ძირითადად ip addr ან მოკლედ ip a.

Windows:

ipconfig

Linux:

ip addr

ან:

ip a

ამ ბრძანებებით შეგვიძლია ვნახოთ ქსელური ინტერფეისები და მათი IP მისამართები. მაგალითად, შეგვიძლია შევამოწმოთ, მიიღო თუ არა კომპიუტერმა IPv4 მისამართი, რა Subnet Mask აქვს და რომელი ქსელური ინტერფეისი გამოიყენება. Windows-ში უფრო დეტალური ინფორმაციისთვის გამოიყენება ipconfig /all.

Windows:

ipconfig /all

Linux-ში დამატებითი ქსელური ინფორმაციის სანახავად გამოიყენება:

ip addr
ip route

შემდეგი მნიშვნელოვანი შემოწმებაა კავშირის ტესტირება. ამისთვის ორივე სისტემაში გამოიყენება ping.

Windows:

ping 8.8.8.8

Linux:

ping 8.8.8.8

ping აგზავნის ICMP Echo Request-ს დანიშნულების მოწყობილობისკენ და ამოწმებს, მოდის თუ არა პასუხი. თუ პასუხი მოდის, ეს მიუთითებს, რომ დანიშნულებამდე ქსელური კავშირი გარკვეულ დონეზე მუშაობს.

მაგალითად, თუ:

ping 192.168.1.1

მუშაობს, მაგრამ:

ping 8.8.8.8

არ მუშაობს, შეიძლება პრობლემა იყოს ადგილობრივ ქსელსა და ინტერნეტს შორის, მაგალითად Gateway-ზე ან ISP-ის მხარეს. თუ 8.8.8.8-ზე ping მუშაობს, მაგრამ google.com-ზე არა, უკვე DNS-ის შემოწმება ხდება საჭირო.

DNS-ის შესამოწმებლად Windows-ში ხშირად გამოიყენება:

nslookup google.com

Linux-ში შეიძლება გამოვიყენოთ:

nslookup google.com

ან:

dig google.com

ორივე სისტემაში nslookup შეიძლება DNS-ის სწრაფი შემოწმებისთვის გამოვიყენოთ. Linux-ში dig უფრო დეტალურ DNS ინფორმაციას გვაძლევს.

მაგალითად, თუ:

ping 8.8.8.8

მუშაობს, მაგრამ:

ping google.com

არ მუშაობს, ხოლო nslookup google.com პრობლემას აჩვენებს, შესაძლებელია DNS-ის პრობლემა გვქონდეს. ეს მნიშვნელოვანი განსხვავებაა, რადგან ასეთ შემთხვევაში ინტერნეტთან კავშირი შეიძლება არსებობდეს, მაგრამ დომენური სახელების IP მისამართებად გადაყვანა ვერ ხდებოდეს.

შემდეგი მნიშვნელოვანი საკითხია Routing. Windows-ში Routing Table-ის სანახავად გამოიყენება:

route print

Linux-ში:

ip route

Routing Table გვიჩვენებს, რომელ ქსელამდე რომელი გზით უნდა გაიგზავნოს პაკეტი. მაგალითად, Linux-ში შეიძლება ვნახოთ:

default via 192.168.1.1

ეს ნიშნავს, რომ სხვა ქსელებისკენ მიმავალი ტრაფიკისთვის ნაგულისხმევი Gateway არის 192.168.1.1.

Windows-ში იგივე იდეა route print-ის შედეგში ჩანს Default Route-ის სახით.

ქსელის გზის შესამოწმებლად Windows-ში გამოიყენება:

tracert google.com

Linux-ში ხშირად გამოიყენება:

traceroute google.com

ამ ბრძანებების მიზანია ვნახოთ, დაახლოებით რა ჰოპების გავლით მიდის ტრაფიკი დანიშნულებამდე. მაგალითად:

PC → Router → ISP → სხვა Router → ... → Destination

თუ რომელიმე ეტაპზე პრობლემა ჩნდება, tracert ან traceroute შეიძლება დაგვეხმაროს იმის გარკვევაში, სად წყდება გზა. თუმცა ერთი ჰოპისგან პასუხის არქონა ავტომატურად არ ნიშნავს, რომ ქსელი გაფუჭებულია, რადგან ზოგიერთი მოწყობილობა ICMP/TTL შეტყობინებებს შეგნებულად ზღუდავს.

შემდეგ შეგვიძლია შევამოწმოთ ARP-ის ინფორმაცია. Windows-ში გამოიყენება:

arp -a

Linux-ში თანამედროვე სისტემებში შეიძლება გამოვიყენოთ:

ip neigh

ეს გვიჩვენებს ადგილობრივ ქსელში IP მისამართებთან დაკავშირებულ MAC Address ინფორმაციას. მაგალითად, თუ კომპიუტერმა უნდა დაუკავშირდეს Gateway-ს 192.168.1.1-ზე, მას ადგილობრივ ქსელში შესაბამისი MAC მისამართის ცოდნა სჭირდება.

ასევე მნიშვნელოვანია ვიცოდეთ, რომელი პორტები და ქსელური კავშირებია აქტიური. Windows-ში ამისთვის ხშირად გამოიყენება:

netstat -ano

Linux-ში თანამედროვე სისტემებში რეკომენდებულია:

ss -tuln

ან:

ss -tunap

ეს ბრძანებები დაგვეხმარება გავიგოთ, რომელი პორტებია მოსმენაში (Listening), რომელი კავშირებია აქტიური და რომელ პროცესთან შეიძლება იყოს დაკავშირებული კონკრეტული კავშირი.

მაგალითად, თუ Linux Server-ზე Web Server უნდა მუშაობდეს HTTPS-ზე, შეგვიძლია შევამოწმოთ, უსმენს თუ არა რომელიმე პროცესი TCP 443 პორტს.

Linux:

ss -tuln

Windows:

netstat -ano

Windows-ის -o პარამეტრი განსაკუთრებით სასარგებლოა, რადგან გვიჩვენებს პროცესის PID-ს. შემდეგ ამ PID-ის მიხედვით შეგვიძლია დავადგინოთ, რომელი პროგრამა იყენებს კონკრეტულ კავშირს ან პორტს.

Windows-სა და Linux-ში ქსელის პრობლემის დიაგნოსტიკის ლოგიკა დაახლოებით ერთი და იგივეა:

1. შევამოწმოთ IP კონფიგურაცია.

Windows:

ipconfig /all

Linux:

ip addr
ip route

2. შევამოწმოთ ადგილობრივი ქსელის Gateway.

Windows/Linux:

ping 192.168.1.1

3. შევამოწმოთ ინტერნეტთან კავშირი IP-ით.

Windows/Linux:

ping 8.8.8.8

4. შევამოწმოთ DNS.

Windows:

nslookup google.com

Linux:

nslookup google.com
ან
dig google.com

5. თუ საჭიროა, შევამოწმოთ მარშრუტი.

Windows:

tracert google.com

Linux:

traceroute google.com

6. თუ პრობლემა კონკრეტულ სერვისს ეხება, შევამოწმოთ პორტები და კავშირები.

Windows:

netstat -ano

Linux:

ss -tuln

7. საჭიროების შემთხვევაში შევამოწმოთ ARP/Neighbor ინფორმაცია.

Windows:

arp -a

Linux:

ip neigh

მნიშვნელოვანია გვახსოვდეს, რომ ყველა ბრძანება სხვადასხვა კითხვას პასუხობს. ipconfig ან ip addr გვეუბნება რა ქსელური კონფიგურაცია აქვს მოწყობილობას. ping ამოწმებს მიაღწევს თუ არა კავშირი დანიშნულებამდე. nslookup და dig ამოწმებს DNS-ის მუშაობას. route print და ip route გვიჩვენებს როგორ არის მარშრუტიზაცია მოწყობილი. tracert და traceroute გვიჩვენებს რა გზით მიდის ტრაფიკი. arp -a და ip neigh გვაძლევს ინფორმაციას ადგილობრივ IP↔MAC შესაბამისობებზე, ხოლო netstat და ss გვიჩვენებს ქსელურ კავშირებსა და პორტებს.

სისტემურ ადმინისტრირებაში მთავარი არ არის ყველა ბრძანების შემთხვევით გაშვება. საჭიროა პრობლემის ეტაპობრივად შევიწროება. მაგალითად, თუ მომხმარებელი ამბობს „ინტერნეტი არ მაქვს“, ჯერ ვამოწმებთ IP კონფიგურაციას, შემდეგ Gateway-ს, შემდეგ გარე IP-ს და ბოლოს DNS-ს. ამ გზით შეგვიძლია გავიგოთ, პრობლემა კომპიუტერშია, ლოკალურ ქსელში, Gateway-ში, ინტერნეტთან კავშირში თუ DNS-ში.

მოკლედ:

Windows | Linux | დანიშნულება

ipconfig /all | ip addr | IP კონფიგურაცია
ping | ping | კავშირის შემოწმება
nslookup | nslookup / dig | DNS-ის შემოწმება
route print | ip route | Routing Table
tracert | traceroute | ქსელის გზის შემოწმება
arp -a | ip neigh | IP ↔ MAC ინფორმაცია
netstat -ano | ss -tuln | კავშირები და პორტები

ამ ბრძანებების ცოდნა უკვე გვაძლევს საშუალებას, Windows-სა და Linux-ზე ქსელის პრობლემის დიაგნოსტირება არა უბრალოდ „ინტერნეტი არ მუშაობს“ დონეზე, არამედ კონკრეტული მიზეზის მოძებნით დავიწყოთ.
