Network Monitoring არის ქსელის მდგომარეობის მუდმივი ან პერიოდული დაკვირვების პროცესი. მისი მიზანია გავიგოთ, მუშაობს თუ არა ქსელი ნორმალურად, რამდენად იტვირთება ქსელური მოწყობილობები, არის თუ არა კავშირის შეფერხებები, იზრდება თუ არა ტრაფიკი და ხომ არ ჩნდება ისეთი პრობლემა, რომელიც მომავალში უფრო სერიოზულ გაუმართაობაში შეიძლება გადაიზარდოს.

 კარგი მონიტორინგის დროს შესაძლებელია პრობლემის აღმოჩენა მანამდეც, სანამ მომხმარებელი მას შეამჩნევს. მაგალითად, შეიძლება დავინახოთ, რომ სერვერის ქსელური ინტერფეისი მუდმივად ძალიან დატვირთულია, რომელიმე მოწყობილობა ხშირად კარგავს კავშირს ან კონკრეტულ სერვერთან Latency მნიშვნელოვნად გაიზარდა.

მონიტორინგისას ერთ-ერთი მნიშვნელოვანი მაჩვენებელია Availability, ანუ ხელმისაწვდომობა. ეს გვიჩვენებს, არის თუ არა კონკრეტული მოწყობილობა ან სერვისი ხელმისაწვდომი. მაგალითად, თუ სერვერი უნდა მუშაობდეს მუდმივად, მონიტორინგის სისტემა პერიოდულად ამოწმებს მას და აფიქსირებს, პასუხობს თუ არა.

ამის მარტივი მაგალითია ping. თუ ადმინისტრატორი პერიოდულად აგზავნის ping-ს სერვერის მისამართზე და სერვერი პასუხობს, შეგვიძლია ვნახოთ, რომ მოწყობილობა ქსელიდან ხელმისაწვდომია. თუმცა მხოლოდ ping-ის პასუხი არ ნიშნავს, რომ სერვერზე ყველა სერვისი მუშაობს. მაგალითად, სერვერი შეიძლება პასუხობდეს ping-ზე, მაგრამ მისი Web Server გათიშული იყოს.

ამიტომ მონიტორინგისას ხშირად ამოწმებენ კონკრეტულ პორტებსა და სერვისებსაც. მაგალითად, თუ სერვერი HTTPS ვებსაიტს აწვდის, შეიძლება შემოწმდეს TCP 443 პორტი და თავად ვებ-სერვისის პასუხი. ამ გზით შეიძლება განვასხვავოთ „სერვერი ქსელში ჩანს“ და „სერვერზე კონკრეტული სერვისი მუშაობს“.

კიდევ ერთი მნიშვნელოვანი მაჩვენებელია Latency, ანუ რამდენი დრო სჭირდება პაკეტს დანიშნულებამდე მისვლასა და პასუხის დაბრუნებას. მაგალითად, თუ სერვერთან კავშირის ჩვეულებრივი Latency დაახლოებით 20 ms არის და გარკვეულ მომენტში 300 ms-მდე იზრდება, ეს შეიძლება მიუთითებდეს ქსელის დატვირთვაზე, მარშრუტის ცვლილებაზე ან სხვა პრობლემაზე. მაღალი Latency განსაკუთრებით შესამჩნევია ონლაინ თამაშებში, VoIP ზარებსა და რეალურ დროში სხვა აპლიკაციებში.

ასევე მნიშვნელოვანია Packet Loss, ანუ პაკეტების დაკარგვა. მაგალითად, თუ 100 პაკეტიდან მხოლოდ 95 მივიდა დანიშნულებამდე, Packet Loss დაახლოებით 5%-ია. Packet Loss შეიძლება გამოწვეული იყოს ქსელის გადატვირთვით, ცუდი კაბელით, Wi-Fi-ს პრობლემებით, ქსელური მოწყობილობის გაუმართაობით ან სხვა მიზეზით.

მონიტორინგისას ყურადღება ექცევა Bandwidth-სა და Network Traffic-საც. Bandwidth არის კავშირის გამტარუნარიანობა, ხოლო Traffic გვიჩვენებს, რამდენი მონაცემი გადის კავშირზე კონკრეტულ მომენტში. მაგალითად, თუ სერვერს აქვს 1 Gbps ქსელური ინტერფეისი და მისი ტრაფიკი მუდმივად ძალიან ახლოს არის ამ ზღვართან, შეიძლება საჭირო გახდეს მიზეზის მოძებნა ან ქსელის რესურსის გაზრდა.

მნიშვნელოვანია ასევე Network Interface-ის მდგომარეობა. ადმინისტრატორს შეუძლია შეამოწმოს, არის თუ არა ქსელური ინტერფეისი აქტიური, რამდენი პაკეტი მიიღო ან გაგზავნა, არის თუ არა შეცდომები და ხომ არ ხდება პაკეტების დაკარგვა. Linux-ში ამისთვის შეიძლება გამოყენებულ იქნას ip -s link, ხოლო Windows-ში ქსელური ადაპტერის სტატისტიკისა და მდგომარეობის სანახავად გამოიყენება შესაბამისი სისტემური ინსტრუმენტები და PowerShell-ის ბრძანებები.

დიდ ქსელებში ადმინისტრატორები ხშირად იყენებენ სპეციალურ Network Monitoring Software-ს. ასეთი სისტემები შეიძლება აკვირდებოდეს Routers, Switches, Servers, Access Points და სხვა მოწყობილობებს. მონიტორინგის პროგრამა აგროვებს ინფორმაციას და აჩვენებს მას Dashboard-ზე, აგზავნის Alert-ს პრობლემის აღმოჩენისას და ზოგჯერ ინახავს ისტორიულ მონაცემებსაც.

მაგალითად, ადმინისტრატორმა შეიძლება დააყენოს წესი:

CPU > 90% → Alert

ან:

Packet Loss > 5% → Alert

ან:

Server unavailable → Alert

ამ შემთხვევაში ადმინისტრატორს შეუძლია პრობლემა შეამჩნიოს მომხმარებლის საჩივრის მიღებამდე.

Network Monitoring-ს ხშირად უკავშირდება SNMP (Simple Network Management Protocol). SNMP გამოიყენება ქსელური მოწყობილობებიდან სხვადასხვა სტატისტიკისა და მდგომარეობის შესახებ ინფორმაციის მისაღებად. მაგალითად, SNMP-ის საშუალებით მონიტორინგის სისტემამ შეიძლება Router-ისგან ან Switch-ისგან მიიღოს ინფორმაცია ინტერფეისის მდგომარეობის, ტრაფიკისა და სხვა მაჩვენებლების შესახებ.

მნიშვნელოვანია გავარჩიოთ Monitoring და Troubleshooting. Monitoring ძირითადად გულისხმობს ქსელის მდგომარეობაზე დაკვირვებას და პრობლემის ადრეულ აღმოჩენას, ხოლო Troubleshooting არის უკვე არსებული პრობლემის მიზეზის მოძებნა და გამოსწორება. მაგალითად, Monitoring სისტემამ შეიძლება დააფიქსიროს, რომ სერვერთან Packet Loss გაიზარდა. ამის შემდეგ ადმინისტრატორი იწყებს Troubleshooting-ს და ამოწმებს კაბელს, Switch-ის პორტს, ქსელურ დატვირთვას, მოწყობილობის სტატისტიკას და სხვა შესაძლო მიზეზებს.

საბოლოოდ, Network Monitoring-ის მთავარი მიზანია ქსელის მდგომარეობის კონტროლი, პრობლემების დროული აღმოჩენა და ქსელის მუშაობის შესახებ ისტორიული ინფორმაციის მიღება. სისტემური ადმინისტრატორისთვის მნიშვნელოვანია იცოდეს მინიმუმ ძირითადი მაჩვენებლები: Availability, Latency, Packet Loss, Bandwidth, Traffic და Interface Errors.

მარტივი მაგალითით:

Monitoring → პრობლემის აღმოჩენა → Alert → Troubleshooting → მიზეზის დადგენა → პრობლემის გამოსწორება

ამიტომ Network Monitoring სისტემურ ადმინისტრირებაში მხოლოდ „ინტერნეტი მუშაობს თუ არა“ შემოწმებას არ ნიშნავს — ის ქსელის ჯანმრთელობის მუდმივ კონტროლს გულისხმობს.
