Network Service არის სერვისი, რომელიც ქსელის საშუალებით სხვა მოწყობილობებს ან პროგრამებს კონკრეტულ ფუნქციას აწვდის. ქსელში სხვადასხვა მოწყობილობის ერთმანეთთან დაკავშირება მხოლოდ IP მისამართებით არ შემოიფარგლება — მათ სჭირდებათ კონკრეტული სერვისები, რომლებიც უზრუნველყოფენ მისამართების ავტომატურ გაცემას, დომენების IP მისამართებად გადაყვანას, ვებგვერდების მიწოდებას, დისტანციურ წვდომას, ფაილების გადაცემას და სხვა ფუნქციებს.

ერთ-ერთი ყველაზე მნიშვნელოვანი ქსელური სერვისია DHCP (Dynamic Host Configuration Protocol). DHCP მოწყობილობებს ავტომატურად აძლევს ქსელში მუშაობისთვის საჭირო პარამეტრებს. მაგალითად, კომპიუტერს შეიძლება მიეცეს IP Address, Subnet Mask, Default Gateway და DNS Server. სახლში DHCP Server-ის ფუნქციას ხშირად როუტერი ასრულებს. ამიტომ როდესაც ლეპტოპი Wi-Fi-ს უერთდება, ჩვეულებრივ ხელით არ გვჭირდება IP მისამართის შეყვანა — როუტერი მას DHCP-ის საშუალებით აძლევს.

შემდეგი მნიშვნელოვანი სერვისია DNS (Domain Name System). DNS ადამიანისათვის მარტივად დასამახსოვრებელ დომენურ სახელს IP მისამართთან აკავშირებს. მაგალითად, როდესაც ბრაუზერში ვწერთ google.com, კომპიუტერს სჭირდება Google-ის სერვერის IP მისამართის ცოდნა. DNS ამ სახელის შესაბამის IP მისამართად გადაყვანაში გვეხმარება. ამიტომ DNS შეგვიძლია წარმოვიდგინოთ როგორც ინტერნეტის „სახელების სისტემა“.

HTTP (Hypertext Transfer Protocol) არის პროტოკოლი, რომელსაც ვებ-ბრაუზერი და Web Server ვებრესურსების გადასაცემად იყენებენ. როდესაც ბრაუზერში ვებგვერდს ვხსნით, ბრაუზერი HTTP-ის საშუალებით აგზავნის მოთხოვნას Web Server-ისკენ, ხოლო სერვერი პასუხს აბრუნებს.

HTTPS (HTTP Secure) არის HTTP-ის დაცული ვარიანტი. HTTPS-ში ვებ-კავშირს ემატება დაშიფვრა, რის გამოც მომხმარებელსა და ვებსაიტის სერვერს შორის გადაცემული მონაცემების დაცვა უფრო მაღალია. HTTPS-ისთვის სტანდარტულად გამოიყენება TCP Port 443, ხოლო HTTP-სთვის — TCP Port 80.

SSH (Secure Shell) არის პროტოკოლი, რომელიც ძირითადად გამოიყენება დისტანციურ მოწყობილობასა და სერვერზე უსაფრთხო წვდომისთვის. მაგალითად, სისტემურ ადმინისტრატორს შეუძლია თავისი კომპიუტერიდან SSH-ის საშუალებით Linux Server-ზე შევიდეს და ბრძანებები დისტანციურად შეასრულოს. SSH-ის სტანდარტული პორტია TCP 22.

FTP (File Transfer Protocol) გამოიყენება ფაილების ქსელის საშუალებით გადასაცემად. მაგალითად, FTP Server-ზე შესაძლებელია ფაილების ატვირთვა ან ჩამოტვირთვა. თუმცა FTP-ის კლასიკური ვარიანტი თანამედროვე უსაფრთხოების მოთხოვნებისთვის პრობლემურია, რადგან მონაცემების გადაცემისას დაშიფვრას არ უზრუნველყოფს. ამიტომ პრაქტიკაში შეიძლება შეგვხვდეს უფრო დაცული ვარიანტები, მაგალითად SFTP, რომელიც SSH-ის მეშვეობით ფაილების უსაფრთხო გადაცემას უზრუნველყოფს.

ამ სერვისებს ერთმანეთისგან განსხვავებული ფუნქციები აქვთ. მაგალითად, DHCP გვეხმარება ქსელური კონფიგურაციის მიღებაში, DNS გვეხმარება სახელის IP მისამართად გადაყვანაში, HTTP/HTTPS გამოიყენება ვებრესურსებისთვის, SSH — დისტანციური ადმინისტრირებისთვის, ხოლო FTP/SFTP — ფაილების გადასაცემად.

ამ სერვისებთან ხშირად დაკავშირებულია კონკრეტული პორტები, რადგან ერთი კომპიუტერი შეიძლება ერთდროულად რამდენიმე ქსელურ სერვისს აწარმოებდეს. მაგალითად:

DNS → 53
SSH → 22
HTTP → 80
HTTPS → 443

პორტი საშუალებას აძლევს ქსელურ ტრაფიკს კონკრეტულ სერვისამდე მიაღწიოს. ამიტომ სისტემურ ადმინისტრირებაში მნიშვნელოვანია ვიცოდეთ არა მხოლოდ სერვისის სახელი, არამედ მისი დანიშნულება და ხშირად გამოყენებული პორტიც.

მაგალითად, თუ Linux Server-ზე ვებგვერდი მუშაობს, შეიძლება ერთდროულად გვქონდეს:

Server IP: 192.168.1.100

192.168.1.100:22 → SSH
192.168.1.100:80 → HTTP
192.168.1.100:443 → HTTPS

ეს ერთი სერვერია, მაგრამ სხვადასხვა პორტზე სხვადასხვა ქსელურ სერვისს შეიძლება ემსახურებოდეს.

სისტემურ ადმინისტრირებაში Network Services-ის ცოდნა განსაკუთრებით მნიშვნელოვანია პრობლემების დიაგნოსტიკის დროს. თუ მომხმარებელი ამბობს, რომ „ინტერნეტი არ მუშაობს“, შეიძლება პრობლემა საერთოდ ინტერნეტკავშირში არ იყოს. მაგალითად, თუ IP მისამართი სწორად აქვს, მაგრამ დომენური სახელები არ იხსნება, შესაძლოა DNS-ის პრობლემა იყოს. თუ IP-ით სერვერი ხელმისაწვდომია, მაგრამ კონკრეტული ვებგვერდი არ იხსნება, შეიძლება HTTP/HTTPS სერვისთან ან Firewall-ის წესთან იყოს დაკავშირებული პრობლემა. თუ ადმინისტრატორი ვერ შედის სერვერზე SSH-ით, საჭიროა შემოწმდეს სერვერის ხელმისაწვდომობა, SSH სერვისი, პორტი და Firewall.

ამიტომ ქსელის პრობლემის დროს მნიშვნელოვანია პრობლემის კონკრეტულ ნაწილამდე დაყვანა: ქსელური კავშირი მუშაობს? IP კონფიგურაცია სწორია? DNS მუშაობს? კონკრეტული სერვისი მუშაობს? საჭირო პორტი ხელმისაწვდომია? Firewall ხომ არ ბლოკავს კავშირს?

საბოლოოდ, Network Services არის ქსელში სხვადასხვა ფუნქციის მომწოდებელი სერვისების ერთობლიობა. სისტემურ ადმინისტრატორს მათი ცოდნა სჭირდება იმისთვის, რომ შეძლოს სერვერების გამართვა, ქსელის მართვა და პრობლემების სწორად დიაგნოსტიკა.

მთავარი სერვისები, რომლებიც ამ ეტაპზე უნდა გახსოვდეს:

DHCP — ავტომატურად იძლევა ქსელურ კონფიგურაციას.
DNS — დომენურ სახელს IP მისამართთან აკავშირებს.
HTTP/HTTPS — ვებრესურსების გადასაცემად გამოიყენება.
SSH — უსაფრთხო დისტანციური ადმინისტრირებისთვის გამოიყენება.
FTP/SFTP — ფაილების გადასაცემად გამოიყენება.
