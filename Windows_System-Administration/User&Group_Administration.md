Windows-ში User and Group Administration ნიშნავს მომხმარებლების და ჯგუფების შექმნას, მართვას და მათთვის შესაბამისი უფლებების მინიჭებას. სისტემური ადმინისტრატორისთვის ეს ერთ-ერთი ძირითადი ამოცანაა, რადგან კომპიუტერში ან ორგანიზაციის ქსელში თითოეულ ადამიანს არ უნდა ჰქონდეს ყველაფერზე წვდომა.

პირველ რიგში უნდა გავარჩიოთ User Account და User. User Account არის Windows-ში შექმნილი ანგარიში, რომლის საშუალებითაც კონკრეტული ადამიანი სისტემაში იდენტიფიცირდება. ანგარიშს შეიძლება ჰქონდეს username, password და კონკრეტული უფლებები. როდესაც მომხმარებელი Windows-ში შედის, სისტემა ამ ანგარიშის მიხედვით განსაზღვრავს, რა მოქმედებების შესრულება შეუძლია მას.

მაგალითად, შეიძლება კომპიუტერში არსებობდეს ორი ანგარიში: user და Admin. user-ს შეიძლება ჰქონდეს Standard User-ის უფლებები, ხოლო Admin-ს — ადმინისტრატორის უფლებები. ორივე იყენებს ერთსა და იმავე Windows სისტემას, მაგრამ მათი შესაძლებლობები განსხვავებულია.

Windows-ში ძირითადად გვხვდება Standard User და Administrator ტიპის ანგარიშები. Standard User-ს შეუძლია ჩვეულებრივი ყოველდღიური სამუშაოების შესრულება — პროგრამების გამოყენება, ფაილებთან მუშაობა და ა.შ. მაგრამ სისტემისთვის მნიშვნელოვანი ცვლილებების გაკეთებისას შეიძლება ადმინისტრატორის დადასტურება დასჭირდეს.

Administrator-ს გაცილებით ფართო უფლებები აქვს. მას შეუძლია პროგრამების ინსტალაცია, სისტემური პარამეტრების შეცვლა, მომხმარებლებისა და ჯგუფების მართვა, ზოგიერთი სისტემური რესურსის შეცვლა და სხვა ადმინისტრაციული მოქმედებების შესრულება. სწორედ ამიტომ Administrator-ის ანგარიში ყოველდღიური სამუშაოებისთვის მუდმივად გამოყენებული არ უნდა იყოს, თუ ამის საჭიროება არ არსებობს.

აქ ისევ გვხვდება Least Privilege-ის პრინციპი. მისი იდეაა, რომ მომხმარებელს ჰქონდეს მხოლოდ იმდენი უფლება, რამდენიც სამუშაოს შესასრულებლად სჭირდება. თუ ჩვეულებრივ მომხმარებელს ადმინისტრატორის სრული უფლებები არ სჭირდება, მისი Admin-ად დატოვება უსაფრთხოების რისკს ზრდის. თუ ასეთი ანგარიშიდან მავნე პროგრამა გაეშვა, მას შეიძლება გაცილებით მეტი სისტემური ცვლილების გაკეთების შესაძლებლობა ჰქონდეს.

მომხმარებლების მართვისას ძალიან მნიშვნელოვანია Groups. Group არის რამდენიმე მომხმარებლის გაერთიანება ერთ ადმინისტრაციულ ერთეულში. ამის მთავარი უპირატესობა ის არის, რომ თითოეულ მომხმარებელზე უფლებების ცალ-ცალკე მინიჭება აღარ არის საჭირო.

მაგალითად, კომპანიაში შეიძლება არსებობდეს `Finance` ჯგუფი. თუ კომპანიაში ფინანსების განყოფილებაში ათი თანამშრომელია, ადმინისტრატორს შეუძლია ეს ათივე მომხმარებელი `Finance` ჯგუფში მოათავსოს და შემდეგ ჯგუფს მისცეს `Finance` საქაღალდეზე საჭირო უფლებები. შედეგად, ახალი თანამშრომლის დამატებისას უბრალოდ მას ამ ჯგუფში ამატებენ.

Windows-ში არსებობს რამდენიმე ჩაშენებული ჯგუფიც. მაგალითად, `Administrators` ჯგუფის წევრებს ადმინისტრაციული უფლებები აქვთ, ხოლო `Users` ჯგუფი ჩვეულებრივ მომხმარებლებს უკავშირდება. არსებობს სხვა სპეციალური ჯგუფებიც, რომელთა დანიშნულება კონკრეტული სისტემური შესაძლებლობების მართვაა.

აქ მნიშვნელოვანი განსხვავებაა User-სა და Group-ს შორის: User წარმოადგენს კონკრეტულ ანგარიშს, ხოლო Group წარმოადგენს მომხმარებლების გაერთიანებას. Permissions-ის მინიჭებისას ხშირად ჯობია უფლება პირდაპირ მომხმარებელს კი არა, შესაბამის ჯგუფს მიენიჭოს. ამას Group-Based Access Control-ის მიდგომა ეხმარება.

მაგალითად, თუ `Finance` საქაღალდეზე წვდომა მხოლოდ ფინანსების თანამშრომლებს სჭირდებათ, ადმინისტრატორი შეიძლება შექმნას `Finance` ჯგუფი, დაამატოს მასში შესაბამისი მომხმარებლები და საქაღალდეზე permission სწორედ ამ ჯგუფს მისცეს. თუ თანამშრომელი კომპანიიდან წავიდა, მისი ანგარიშის ჯგუფიდან ამოღება საკმარისი იქნება შესაბამისი წვდომის შესაწყვეტად.

მომხმარებლის ანგარიშის მართვა მოიცავს არა მხოლოდ შექმნას, არამედ Disable-ს, Password-ის შეცვლას და საჭიროების შემთხვევაში ანგარიშის წაშლასაც. მაგალითად, თუ თანამშრომელი დროებით აღარ მუშაობს კომპანიაში, ანგარიშის წაშლის ნაცვლად შეიძლება მისი Disable გაკეთდეს. ასეთ შემთხვევაში ანგარიში და მასთან დაკავშირებული ინფორმაცია შეიძლება შენარჩუნდეს, მაგრამ მომხმარებელი ვეღარ შევა სისტემაში.

Password-ის მართვაც ადმინისტრირების ნაწილია. ადმინისტრატორმა უნდა უზრუნველყოს ძლიერი პაროლების გამოყენება და საჭიროების შემთხვევაში პაროლის შეცვლა. ორგანიზაციულ გარემოში შეიძლება არსებობდეს Password Policy, რომელიც განსაზღვრავს პაროლის სირთულეს, მინიმალურ სიგრძეს და სხვა წესებს.

Windows-ის ლოკალური მომხმარებლებისა და ჯგუფების სამართავად არსებობს `lusrmgr.msc` — Local Users and Groups. აქ ადმინისტრატორს შეუძლია მომხმარებლებისა და ჯგუფების ნახვა, შექმნა, Disable/Enable და სხვა პარამეტრების მართვა. თუმცა ზოგიერთი Windows გამოცემა ამ კონსოლს სრულად არ შეიცავს.

ასევე შესაძლებელია მომხმარებლებისა და ჯგუფების მართვა ბრძანების ხაზიდან. მაგალითად:

`net user`

აჩვენებს ლოკალურ მომხმარებლებს.

`net user username`

აჩვენებს კონკრეტული მომხმარებლის ინფორმაციას.

ჯგუფების სანახავად შეიძლება გამოყენებულ იქნას:

`net localgroup`

ეს განსაკუთრებით სასარგებლოა მაშინ, როდესაც ადმინისტრატორს GUI-ის ნაცვლად Command Prompt-იდან სურს ინფორმაციის მიღება ან გარკვეული მოქმედების შესრულება.

PowerShell-შიც შესაძლებელია მომხმარებლებისა და ჯგუფების ადმინისტრირება. მაგალითად, სისტემური ადმინისტრირების უფრო თანამედროვე გარემოში გამოიყენება შესაბამისი PowerShell cmdlet-ები და ეს განსაკუთრებით სასარგებლო ხდება მაშინ, როდესაც ბევრი კომპიუტერის ან მომხმარებლის მართვაა საჭირო.

User Administration-ს კიდევ ერთი მნიშვნელოვანი ნაწილი არის Account Lockout. თუ მომხმარებელი ბევრჯერ შეიყვანს არასწორ პაროლს, სისტემაში შეიძლება ჩაირთოს ანგარიშის დროებითი დაბლოკვა. ეს უსაფრთხოების მექანიზმია, რომელიც brute-force ტიპის მცდელობების წინააღმდეგ გამოიყენება.

აქ უნდა გავარჩიოთ Authentication და Authorization. Authentication პასუხობს კითხვას: „ვინ ხარ?“ მაგალითად, მომხმარებელი შედის თავისი username და password-ით. Authorization კი პასუხობს კითხვას: „რისი გაკეთების უფლება გაქვს?“ მომხმარებელი შეიძლება წარმატებით დადასტურდეს, მაგრამ კონკრეტულ საქაღალდეზე ან სისტემურ ფუნქციაზე წვდომა მაინც არ ჰქონდეს.

ეს განსხვავება განსაკუთრებით მნიშვნელოვანია File Sharing-ის დროს. მაგალითად, თანამშრომელმა შეიძლება წარმატებით გაიაროს Authentication და შევიდეს Windows-ში, მაგრამ `Finance` საქაღალდეზე წვდომა არ ჰქონდეს, რადგან Authorization-ის დონეზე შესაბამისი permission არ გააჩნია.

User and Group Administration-ის საბოლოო მიზანია სისტემაში წვდომის სწორად ორგანიზება. ადმინისტრატორი ქმნის მომხმარებლებს, აერთიანებს მათ შესაბამის ჯგუფებში, ანიჭებს საჭირო უფლებებს და საჭიროების შემთხვევაში აუქმებს ან ზღუდავს ამ უფლებებს.

ამ ყველაფრის ძირითადი ლოგიკა ასეთია: **User → Group → Permission → Resource**. მომხმარებელი არის კონკრეტული ანგარიში, ჯგუფი აერთიანებს მომხმარებლებს, permission განსაზღვრავს მათ შესაძლებლობებს, ხოლო resource არის ის, რაზეც წვდომა სჭირდებათ — მაგალითად ფაილი, საქაღალდე, პრინტერი ან სისტემური ფუნქცია.

კარგი ადმინისტრაცია ნიშნავს არა იმას, რომ ყველას ჰქონდეს მაქსიმალური უფლებები, არამედ იმას, რომ თითოეულ მომხმარებელს ჰქონდეს ზუსტად ის წვდომა, რაც სამუშაოსთვის სჭირდება.
