Windows-ში File Sharing ნიშნავს ფაილებისა და საქაღალდეების ქსელში გაზიარებას ისე, რომ სხვა კომპიუტერიდან მათი ნახვა და გამოყენება იყოს შესაძლებელი. მაგალითად, ოფისში შეიძლება ერთი კომპიუტერი ან სერვერი შეიცავდეს საერთო საქაღალდეს, სადაც თანამშრომლები დოკუმენტებს ინახავენ. ასეთ შემთხვევაში ფაილის USB-ით გადატანა საჭირო აღარ არის — მომხმარებელი მას ქსელის საშუალებით წვდება.

ქსელში გაზიარებული საქაღალდე ჩვეულებრივი საქაღალდისგან იმით განსხვავდება, რომ მასზე ქსელიდანაც შეიძლება წვდომა. Windows-ში ამისთვის გამოიყენება SMB — Server Message Block. SMB არის პროტოკოლი, რომლის საშუალებითაც Windows კომპიუტერები ქსელში ფაილებს, საქაღალდეებს და სხვა რესურსებს აზიარებენ.

მაგალითად, თუ კომპიუტერს სახელად `PC01` აქვს გაზიარებული `Documents` საქაღალდე, სხვა კომპიუტერიდან მასზე წვდომა შეიძლება ქსელური გზით:

`\\PC01\Documents`

აქ `PC01` არის კომპიუტერის სახელი, ხოლო `Documents` — გაზიარებული რესურსის სახელი. იგივე შეიძლება გაკეთდეს IP მისამართითაც:

`\\192.168.1.10\Documents`

ამ ფორმატს UNC Path ეწოდება. UNC Path-ის საშუალებით Windows-ს ვეუბნებით, რომელ კომპიუტერზე და რომელ გაზიარებულ რესურსზე გვინდა წვდომა.

მაგრამ მხოლოდ საქაღალდის გაზიარება არ ნიშნავს, რომ ნებისმიერ ადამიანს ყველაფრის გაკეთება შეუძლია. აქ უკვე ჩნდება Permissions — უფლებები. Windows-ში ფაილზე ან საქაღალდეზე წვდომისას მნიშვნელოვანია როგორც Share Permissions, ისე NTFS Permissions.

Share Permissions მოქმედებს მაშინ, როდესაც რესურსს ქსელიდან ვწვდებით. მაგალითად, შეიძლება მომხმარებელს გაზიარებულ საქაღალდეზე ჰქონდეს Read უფლება და მხოლოდ ფაილების ნახვა შეეძლოს, ხოლო სხვა მომხმარებელს ჰქონდეს Change ან Full Control-ის შესაბამისი შესაძლებლობა.

NTFS Permissions კი თვითონ ფაილური სისტემის დონეზე მოქმედებს. მაგალითად, საქაღალდეზე შეიძლება კონკრეტულ მომხმარებელს ჰქონდეს Read, Modify ან Full Control. როდესაც მომხმარებელი ქსელიდან შედის გაზიარებულ NTFS საქაღალდეში, საბოლოო წვდომაზე ორივე ტიპის უფლება შეიძლება იმოქმედოს.

მნიშვნელოვანი პრინციპია, რომ ქსელიდან წვდომისას Share და NTFS უფლებები ერთად უნდა გავითვალისწინოთ. პრაქტიკულად, მომხმარებლის რეალური შესაძლებლობა შეზღუდული იქნება იმ დონით, რასაც ორივე permission სისტემა აძლევს. მაგალითად, თუ Share დონეზე მომხმარებელს მხოლოდ Read აქვს, მაგრამ NTFS-ზე Modify აქვს, ქსელიდან ის მაინც მხოლოდ Read-ის შესაძლებლობას მიიღებს.

File Sharing-ის დროს ასევე მნიშვნელოვანია Authentication. Windows-მა უნდა იცოდეს, ვინ ცდილობს რესურსზე შესვლას. ამისთვის შეიძლება მომხმარებელს დასჭირდეს შესაბამისი Windows ანგარიში და პაროლი. ორგანიზაციაში ეს განსაკუთრებით მნიშვნელოვანია, რადგან თითოეულ თანამშრომელს შეიძლება განსხვავებული წვდომა ჰქონდეს.

მაგალითად, კომპანიაში შეიძლება არსებობდეს საერთო საქაღალდე `Company`, რომლის შიგნით არის `Finance`, `HR` და `Public`. ფინანსების თანამშრომლებს `Finance` საქაღალდეზე ექნებათ საჭირო უფლებები, HR-ის თანამშრომლებს — `HR`-ზე, ხოლო `Public` შეიძლება ყველასთვის ხელმისაწვდომი იყოს. ამ გზით ადმინისტრატორი განსაზღვრავს, ვინ რომელ მონაცემს ხედავს და ცვლის.

Windows-ში ქსელური გაზიარებისთვის მნიშვნელოვანია Network Discovery და File and Printer Sharing. Network Discovery ეხმარება კომპიუტერს ქსელში სხვა მოწყობილობებისა და რესურსების აღმოჩენაში, ხოლო File and Printer Sharing საშუალებას იძლევა ფაილებისა და პრინტერების გაზიარება მოხდეს ქსელში.

თუ გაზიარებული საქაღალდე სხვა კომპიუტერიდან არ იხსნება, პრობლემა შეიძლება სხვადასხვა ადგილას იყოს. მაგალითად, კომპიუტერებს შორის ქსელური კავშირი შეიძლება არ მუშაობდეს, Windows Firewall ბლოკავდეს SMB ტრაფიკს, File and Printer Sharing გამორთული იყოს, მომხმარებელს არ ჰქონდეს შესაბამისი permission ან უბრალოდ არასწორი UNC Path იყოს გამოყენებული.

ამიტომ ადმინისტრატორი პრობლემას ეტაპობრივად ამოწმებს. პირველ რიგში ამოწმებს, უკავშირდებიან თუ არა კომპიუტერები ერთმანეთს. შემდეგ ამოწმებს კომპიუტერის სახელს ან IP მისამართს, გაზიარების არსებობას, Network Discovery-სა და File and Printer Sharing-ს, Firewall-ს და ბოლოს მომხმარებლის უფლებებს.

ქსელური რესურსის კიდევ ერთი მნიშვნელოვანი შესაძლებლობაა Map Network Drive. Windows-ში ქსელური საქაღალდე შეიძლება ჩვეულებრივ დისკს დაემსგავსოს და მას მიენიჭოს ასო, მაგალითად `Z:`. მომხმარებლისთვის ეს უკვე ჩვეულებრივი დისკივით გამოჩნდება File Explorer-ში, მაგრამ სინამდვილეში მონაცემები ქსელში მდებარე სხვა კომპიუტერიდან ან სერვერიდან მოდის.

მაგალითად, ადმინისტრატორმა შეიძლება `\\Server01\Shared` რესურსი `Z:` დისკად დააკავშიროს. ამის შემდეგ მომხმარებელი File Explorer-ში უბრალოდ `Z:`-ს გახსნის და იქ არსებულ ფაილებს გამოიყენებს.

აქ მნიშვნელოვანია განსხვავება Local Resource-სა და Network Resource-ს შორის. Local Resource უშუალოდ იმ კომპიუტერის დისკზე ან სხვა ადგილობრივ მოწყობილობაზე მდებარეობს, რომელსაც მომხმარებელი იყენებს. Network Resource კი სხვა კომპიუტერზე, სერვერზე ან ქსელურ მოწყობილობაზე მდებარეობს და მასზე ქსელის საშუალებით ხდება წვდომა.

File Sharing-ის ადმინისტრირებისას უსაფრთხოებაც ძალიან მნიშვნელოვანია. ყველა საქაღალდის ყველასთვის Full Control-ით გაზიარება ცუდი პრაქტიკაა. უკეთესი მიდგომაა Least Privilege — მომხმარებელს მიეცეს მხოლოდ ის უფლებები, რომლებიც რეალურად სჭირდება. მაგალითად, თუ თანამშრომელს მხოლოდ დოკუმენტების წაკითხვა სჭირდება, მას Modify ან Full Control აუცილებელი არ არის.

ამიტომ Windows File Sharing-ის მთავარი სურათი ასეთია: ერთი კომპიუტერი ან სერვერი აზიარებს საქაღალდეს SMB-ის საშუალებით, სხვა კომპიუტერი მას UNC Path-ით უკავშირდება, Windows ამოწმებს მომხმარებლის ვინაობას და შემდეგ permissions-ის მიხედვით წყვეტს, რა შეუძლია მას — მხოლოდ ნახვა, ფაილის შეცვლა, შექმნა, წაშლა თუ სრული კონტროლი.

სისტემური ადმინისტრატორისთვის ყველაზე მნიშვნელოვანი სწორედ ეს კავშირია: Network Connectivity → SMB/File Sharing → Authentication → Permissions → Access. თუ ამ ჯაჭვის რომელიმე ნაწილი არ მუშაობს, მომხმარებელი ქსელურ ფაილზე წვდომას ვერ მიიღებს.
