Windows-ში მონაცემები ინახება ფაილებად და საქაღალდეებად, მაგრამ იმისთვის, რომ ოპერაციულმა სისტემამ სწორად მართოს ეს მონაცემები, საჭიროა File System. File System განსაზღვრავს, როგორ ინახება ფაილები დისკზე, როგორ ხდება მათი მოძებნა და როგორ იმართება მათზე წვდომა.

Windows-ის ყველაზე მნიშვნელოვანი File System არის **NTFS — New Technology File System**. NTFS თანამედროვე Windows სისტემებში ძირითადი ფაილური სისტემაა და მას მხოლოდ ფაილების შენახვა არ ევალება. მისი ერთ-ერთი მთავარი უპირატესობაა ფაილებსა და საქაღალდეებზე **Permissions**, ანუ უფლებების მინიჭების შესაძლებლობა.

 საქაღალდეში შეიძლება იყოს სხვადასხვა თანამშრომლის ფაილები. სისტემას უნდა შეეძლოს განსაზღვროს, ვინ შეძლებს ამ ფაილების წაკითხვას, ვინ შეცვლის მათ და ვინ საერთოდ ვერ შევა საქაღალდეში. სწორედ ამას ემსახურება Permissions.

Windows-ში NTFS Permissions-ის ძირითადი უფლებებია **Read, Write, Read & Execute, Modify და Full Control**.

**Read** ნიშნავს, რომ მომხმარებელს შეუძლია ფაილის ან საქაღალდის შინაარსის ნახვა და წაკითხვა.

**Write** საშუალებას აძლევს მომხმარებელს მონაცემების შექმნას ან ჩაწერას შესაბამის ადგილას.

**Read & Execute** ნიშნავს, რომ მომხმარებელს შეუძლია ფაილის წაკითხვა და პროგრამის შემთხვევაში მისი გაშვება.

**Modify** უფრო ფართო უფლებაა. მომხმარებელს შეუძლია ფაილებისა და საქაღალდეების წაკითხვა, შექმნა, შეცვლა და წაშლა, თუმცა სრული ადმინისტრაციული კონტროლი არ აქვს.

**Full Control** ყველაზე ფართო ძირითადი უფლებაა. მომხმარებელს შეუძლია მონაცემების წაკითხვა, შეცვლა, წაშლა და უფლებების მართვასთან დაკავშირებული მოქმედებების შესრულებაც, შესაბამისი უსაფრთხოების კონტექსტის მიხედვით.

აქ მნიშვნელოვანია გავიგოთ, რომ Permission შეიძლება მიენიჭოს როგორც კონკრეტულ **User-ს**, ისე **Group-ს**. მაგალითად, თუ კომპანიაში ათი თანამშრომელია და ყველა მათგანს ერთ საქაღალდეზე Read უფლება სჭირდება, ადმინისტრატორს არ სჭირდება ათივე მომხმარებლის ცალ-ცალკე კონფიგურაცია. შესაძლებელია მათი ჯგუფში გაერთიანება და შემდეგ ჯგუფისთვის საჭირო უფლების მინიჭება.

NTFS-ში არსებობს **Inheritance**, ანუ უფლებების მემკვიდრეობით გადაცემა. მაგალითად, თუ საქაღალდეზე კონკრეტულ ჯგუფს გარკვეული Permission აქვს, ეს Permission შეიძლება ავტომატურად გავრცელდეს მის შიგნით არსებულ ქვესაქაღალდეებსა და ფაილებზეც.

Inheritance-ის უპირატესობა ის არის, რომ ადმინისტრატორს თითოეული ფაილისთვის ცალ-ცალკე Permission-ის მითითება არ სჭირდება. თუმცა ზოგჯერ კონკრეტულ საქაღალდეზე განსხვავებული წვდომაა საჭირო და ასეთ შემთხვევაში მემკვიდრეობითი უფლებების შეცვლა ან შეწყვეტა შეიძლება გახდეს საჭირო.

კიდევ ერთი მნიშვნელოვანი ცნებაა **Ownership**. Windows-ში ფაილსა და საქაღალდეს ჰყავს Owner — მფლობელი. Owner-ს შეუძლია გარკვეულ შემთხვევებში Permissions-ის მართვაზე გავლენა მოახდინოს. მნიშვნელოვანია გვესმოდეს, რომ **Owner ყოფნა და Full Control Permission ზუსტად ერთი და იგივე არ არის**. Ownership არის მფლობელობის სტატუსი, ხოლო Permission განსაზღვრავს, რა მოქმედებების შესრულებაა ნებადართული.

Windows-ის უსაფრთხოების კიდევ ერთი მნიშვნელოვანი პრინციპია **Least Privilege**. მომხმარებელს არ უნდა მივცეთ იმაზე მეტი უფლება, ვიდრე სამუშაოსთვის სჭირდება. მაგალითად, თუ თანამშრომელს მხოლოდ ანგარიშების წაკითხვა სჭირდება, მისთვის Full Control-ის მიცემა საჭირო არ არის. საკმარისი შეიძლება იყოს Read.

მნიშვნელოვანია ასევე განვასხვავოთ **Authentication** და **Permissions**. Authentication ადგენს, ვინ არის მომხმარებელი. შემდეგ Windows ამოწმებს მის უფლებებს და ადგენს, შეუძლია თუ არა კონკრეტულ რესურსთან წვდომა.

ამიტომ File System და Permissions-ის მთავარი იდეა ასეთია: **File System განსაზღვრავს, როგორ ინახება და იმართება მონაცემები, ხოლო Permissions განსაზღვრავს, ვის შეუძლია ამ მონაცემებზე კონკრეტული მოქმედების შესრულება.** Windows-ში NTFS ამ ორი ამოცანის გაერთიანებაში მნიშვნელოვან როლს ასრულებს.

System Administrator-ისთვის ეს განსაკუთრებით მნიშვნელოვანია, რადგან რეალურ გარემოში ხშირად გვხვდება სიტუაცია, როდესაც მომხმარებელი ამბობს: „ფაილზე წვდომა არ მაქვს“. ადმინისტრატორმა ასეთ დროს უნდა შეამოწმოს მომხმარებლის ანგარიში, ჯგუფის წევრობა, NTFS Permissions, Inheritance და საჭიროების შემთხვევაში Ownership.


FAT32:

FAT32 (File Allocation Table 32) ერთ-ერთი ძველი და დღემდე ფართოდ მხარდაჭერილი ფაილური სისტემაა. მისი მთავარი უპირატესობა არის **თავსებადობა** — FAT32-ს Windows, Linux, macOS, სხვადასხვა ტელევიზორი, სათამაშო კონსოლი, კამერა და სხვა მოწყობილობები ადვილად კითხულობენ. ამიტომ ხშირად გვხვდება USB ფლეშ მეხსიერებებსა და მეხსიერების ბარათებზე.

მისი მთავარი ნაკლი არის **ერთი ფაილის მაქსიმალური ზომა — დაახლოებით 4 GB**. მაგალითად, თუ გაქვს 64 GB-იანი ფლეშკა FAT32 ფორმატში, მასზე შეიძლება თავისუფალი ადგილი იყოს 20 GB, მაგრამ 6 GB-იან ერთ ფაილს მაინც ვერ ჩაწერ.

FAT32-ს თანამედროვე ფაილური სისტემებისგან შედარებით ნაკლები შესაძლებლობა აქვს. მაგალითად, მას არ აქვს NTFS-ის მსგავსი უსაფრთხოების permissions და სხვა თანამედროვე მექანიზმები. ამიტომ სისტემური დისკისთვის Windows-ში FAT32 ჩვეულებრივ საუკეთესო არჩევანი არ არის. მისი მთავარი დანიშნულება უფრო **მაქსიმალური თავსებადობაა**.


exFAT:

exFAT (Extended File Allocation Table) შეიქმნა FAT32-ის ზოგიერთი მნიშვნელოვანი შეზღუდვის მოსაგვარებლად. ის განსაკუთრებით მოსახერხებელია **USB ფლეშებისთვის, გარე SSD/HDD-ებისთვის და დიდი მოცულობის მეხსიერების ბარათებისთვის**, რომლებიც სხვადასხვა ოპერაციულ სისტემასა და მოწყობილობას შორის უნდა გამოიყენო.

FAT32-ისგან განსხვავებით, exFAT-ს **4 GB-იანი ერთი ფაილის შეზღუდვა არ აქვს**, ამიტომ მაგალითად 10 GB-იანი ვიდეოს ან დიდი ISO ფაილის შენახვა შესაძლებელია. ამასთან, exFAT შედარებით მარტივი და მსუბუქი ფაილური სისტემაა და არ არის ორიენტირებული ისეთ ფუნქციებზე, როგორიცაა Windows-ის NTFS permissions.

მაგალითად, თუ გაქვს 128 GB-იანი USB, რომელსაც ხან Windows-ის კომპიუტერში იყენებ, ხან Mac-ში და ხან სხვა მოწყობილობაში, exFAT ხშირად უფრო პრაქტიკული არჩევანია, ვიდრე NTFS ან FAT32. ამიტომ exFAT-ის მთავარი იდეაა **დიდი ფაილები + კარგი თავსებადობა სხვადასხვა სისტემასთან**.

ReFS:

ReFS (Resilient File System) არის Microsoft-ის მიერ შექმნილი უფრო სპეციალიზებული ფაილური სისტემა. მისი მთავარი მიზანი მხოლოდ ფაილების შენახვა კი არა, **მონაცემთა მთლიანობისა და საიმედოობის გაუმჯობესებაა**. სახელწოდებაც სწორედ ამას აღნიშნავს — Resilient File System, ანუ მდგრადი/გამძლე ფაილური სისტემა.

ReFS განსაკუთრებით საინტერესოა **დიდი მოცულობის მონაცემების, სერვერებისა და პროფესიონალური ინფრასტრუქტურისთვის**. მას აქვს ისეთი მექანიზმები, რომლებიც ხელს უწყობს მონაცემთა კორუფციის აღმოჩენასა და გარკვეულ შემთხვევებში მისგან დაცვას. ასევე გათვლილია ძალიან დიდი მოცულობის საცავებთან მუშაობაზე.

ჩვეულებრივი სახლის კომპიუტერის სისტემური დისკისთვის ReFS ჩვეულებრივ საჭირო არ არის. Windows-ის ყოველდღიურ გამოყენებაში NTFS უფრო გავრცელებული არჩევანია. ReFS უფრო მეტად გვხვდება ისეთ გარემოებში, სადაც მნიშვნელოვანია **დიდი საცავი, მონაცემთა მდგრადობა და საიმედოობა**.



ext4:

ext4 (Fourth Extended Filesystem) არის Linux-ის ერთ-ერთი ყველაზე გავრცელებული ფაილური სისტემა და მისი განვითარება ext2/ext3-ის შემდეგ მოხდა. ის შექმნილია იმისთვის, რომ Linux სისტემებში ფაილებისა და დირექტორიების საიმედოდ შენახვა და მართვა უზრუნველყოს. ext4 განსაკუთრებით გავრცელებულია Linux-ის დისტრიბუციებში, მაგალითად Ubuntu-სა და Debian-ში.

ext4 იყენებს journaling-ს, რაც ნიშნავს, რომ მნიშვნელოვანი ცვლილებების შესახებ ინფორმაცია წინასწარ ინახება სპეციალურ ჟურნალში. თუ სისტემა მოულოდნელად გაითიშა ან ელექტროენერგია გაითიშა, journaling ეხმარება ფაილურ სისტემას მდგომარეობის აღდგენაში და ამცირებს კორუფციის რისკს.
ext4-ს შეუძლია დიდი რაოდენობის ფაილებისა და დიდი მოცულობის დისკების მართვა და ყოველდღიური Linux გამოყენებისთვის კარგი წარმადობა და სტაბილურობა აქვს. Linux-ში permissions-იც ძალიან მნიშვნელოვანია: ფაილებსა და დირექტორიებს შეიძლება ჰქონდეთ Read, Write და Execute უფლებები მომხმარებლისთვის, ჯგუფისთვის და სხვა მომხმარებლებისთვის.
მაგალითად, თუ Ubuntu-ს აყენებ და ინსტალაციისას დისკს ext4-ად აფორმატებ, Linux ამ ფაილურ სისტემაში განათავსებს ოპერაციულ სისტემას, პროგრამებს, მომხმარებლის ფაილებს და დირექტორიებს.

მარტივად რომ დავამახსოვროთ: ext4 არის Linux-ისთვის ის ძირითადი და სტაბილური ფაილური სისტემა.
