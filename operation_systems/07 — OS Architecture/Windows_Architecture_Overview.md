Windows Architecture აღწერს, როგორ არის Microsoft Windows-ის ოპერაციული სისტემა შიგნიდან ორგანიზებული და როგორ თანამშრომლობენ მისი ძირითადი კომპონენტები. Windows-ის არქიტექტურის ცოდნა გვეხმარება გავიგოთ, როგორ მუშაობს პროგრამები, როგორ იმართება აპარატურა და როგორ უზრუნველყოფს სისტემა უსაფრთხოებასა და რესურსების განაწილებას.

Windows-ის არქიტექტურა პირობითად შეიძლება ორ მთავარ ნაწილად დავყოთ: User Mode და Kernel Mode. ეს ორი რეჟიმი განსაზღვრავს, რა ტიპის ოპერაციების შესრულება შეუძლია კოდს და რა დონის წვდომა აქვს მას სისტემის რესურსებზე.

User Mode-ში მუშაობს მომხმარებლის პროგრამების უმეტესობა, მაგალითად, ბრაუზერები, ტექსტური რედაქტორები და მრავალი სისტემური აპლიკაცია. ამ რეჟიმში გაშვებულ პროგრამას პირდაპირი, შეუზღუდავი წვდომა არ აქვს Kernel-ის მეხსიერებასა და აპარატურაზე. როდესაც პროგრამას სჭირდება ფაილის წაკითხვა, მეხსიერების გამოყოფა ან ქსელური კომუნიკაცია, ის შესაბამის მოთხოვნას ოპერაციულ სისტემას გადასცემს.

Kernel Mode-ში მუშაობს Windows-ის ბირთვი და სხვა პრივილეგირებული სისტემური კომპონენტები. აქ სრულდება პროცესებისა და ნაკადების მართვასთან, მეხსიერების მართვასთან, აპარატურულ Interrupt-ებთან და მოწყობილობის დრაივერებთან დაკავშირებული მნიშვნელოვანი ფუნქციები. Kernel Mode-ს მაღალი პრივილეგიები აქვს, ამიტომ ამ რეჟიმში მომუშავე კომპონენტში სერიოზულმა შეცდომამ შესაძლოა მთელი სისტემა დააზიანოს.

Windows-ის არქიტექტურის მნიშვნელოვანი ნაწილია Windows Executive. ის აერთიანებს სხვადასხვა სისტემურ კომპონენტს, რომლებიც პასუხისმგებელია პროცესებისა და ნაკადების, ვირტუალური მეხსიერების, I/O ოპერაციების, უსაფრთხოებისა და სხვა რესურსების მართვაზე. მაგალითად, I/O Manager კოორდინირებს შემავალ-გამომავალ ოპერაციებს და შესაბამის დრაივერებთან ურთიერთქმედებას უზრუნველყოფს.

კიდევ ერთი კომპონენტია Windows Kernel, რომელიც დაბალი დონის ფუნქციებს ასრულებს, მათ შორის დაგეგმვასთან, Interrupt-ების დამუშავებასა და სინქრონიზაციის მექანიზმებთან დაკავშირებულ სამუშაოს. Windows Kernel და Windows Executive ერთმანეთთან მჭიდროდ თანამშრომლობენ, თუმცა ისინი ერთი და იგივე კომპონენტი არ არის.

Device Drivers უზრუნველყოფს ოპერაციულ სისტემასა და აპარატურას შორის ურთიერთქმედებას. მაგალითად, გრაფიკული ბარათის ან ქსელური ადაპტერის დრაივერი შესაბამისი მოწყობილობის მართვას ეხმარება. Windows-ში ბევრი დრაივერი Kernel Mode-ში მუშაობს, თუმცა არსებობს User Mode-ში მომუშავე დრაივერებიც.

Windows იყენებს აგრეთვე System Services-სა და System Processes-ს, რომლებიც სხვადასხვა სისტემურ ფუნქციას ასრულებს. ზოგი სერვისი მომხმარებლის რეჟიმში მუშაობს და ისეთ ამოცანებს მართავს, როგორიცაა ქსელური ფუნქციები, სისტემური პოლიტიკები ან სხვა ფონური ოპერაციები.

როდესაც მომხმარებლის პროგრამა სისტემურ მოქმედებას ითხოვს, მაგალითად, ფაილის გახსნას, ის შესაბამის API-ს იყენებს. მოთხოვნა საჭირო სისტემური მექანიზმების გავლით გადაეცემა ოპერაციულ სისტემას. საჭიროების შემთხვევაში შესრულება User Mode-დან Kernel Mode-ში გადადის, სადაც შესაბამისი კომპონენტები მოთხოვნას ამუშავებენ. შემდეგ შედეგი პროგრამას უბრუნდება.

ამრიგად, Windows-ის არქიტექტურა შედგება ურთიერთდაკავშირებული კომპონენტებისგან, რომლებიც პროგრამების შესრულებას, მეხსიერების მართვას, აპარატურასთან კომუნიკაციასა და სისტემის დაცვას უზრუნველყოფს. User Mode-სა და Kernel Mode-ს შორის გამიჯვნა კი უსაფრთხოებისა და სისტემის სტაბილურობის ერთ-ერთი მნიშვნელოვანი საფუძველია.
