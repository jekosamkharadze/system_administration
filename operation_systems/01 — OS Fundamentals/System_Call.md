**System Call** არის მექანიზმი, რომლის საშუალებითაც პროგრამა ოპერაციულ სისტემას სთხოვს კონკრეტული მოქმედების შესრულებას. პროგრამები ხშირად საჭიროებენ ფაილებთან მუშაობას, მეხსიერების გამოყენებას, პროცესების მართვას ან ქსელურ კავშირს. რადგან ჩვეულებრივ პროგრამებს არ აქვთ სისტემის ყველა რესურსზე პირდაპირი და შეუზღუდავი წვდომა, ისინი ამ მოთხოვნებისთვის ოპერაციულ სისტემას მიმართავენ.

მაგალითად, როდესაც Notepad-ში ტექსტს ვწერთ და შენახვის ღილაკს ვაჭერთ, პროგრამამ ფაილში მონაცემები უნდა ჩაწეროს. Notepad ჩვეულებრივ მუშაობს **User Mode-ში**, ამიტომ ის დისკის აპარატურას პირდაპირ არ მართავს. პროგრამა შესაბამის მოთხოვნას ოპერაციულ სისტემას უგზავნის **System Call-ის** საშუალებით. მოთხოვნას Kernel ამუშავებს, საჭიროების შემთხვევაში ამოწმებს წვდომის უფლებებს და ფაილურ სისტემასა და მოწყობილობის დრაივერთან ურთიერთობის ორგანიზებას უზრუნველყოფს. ოპერაციის დასრულების შემდეგ პროგრამა იღებს შედეგს ან შეცდომის შეტყობინებას.

System Call-ები სხვადასხვა დანიშნულებით გამოიყენება. ფაილებთან მუშაობისას ისინი პროგრამას ფაილის გახსნაში, წაკითხვაში, ჩაწერასა და დახურვაში ეხმარება. პროცესების მართვისას გამოიყენება პროცესების შექმნისა და დასრულების მსგავსი ოპერაციებისთვის. მეხსიერების მართვისას პროგრამას შეუძლია ოპერაციულ სისტემას მეხსიერების გამოყოფა ან სხვა მეხსიერებასთან დაკავშირებული მოქმედება მოსთხოვოს. ქსელურ პროგრამებს კი სისტემური ინტერფეისების საშუალებით შეუძლიათ კავშირის შექმნა, მონაცემების გაგზავნა და მიღება.

System Call-ის მუშაობა დაკავშირებულია წინა თემებში განხილულ **User Mode-სა და Kernel Mode-თან**. პროგრამა, როგორც წესი, User Mode-ში მუშაობს. როდესაც მას ისეთი ოპერაცია სჭირდება, რომელიც Kernel-ის ჩარევას მოითხოვს, ის სისტემურ გამოძახებას იყენებს. პროცესორი კონტროლს გადასცემს შესაბამის სისტემურ კოდს, რომელიც პრივილეგირებულ რეჟიმში მუშაობს. Kernel ამუშავებს მოთხოვნას და შემდეგ შესრულება პროგრამას უბრუნდება. ეს გადასვლა კონტროლირებადია და პროგრამას Kernel-ის უფლებებს პირდაპირ არ ანიჭებს.

მნიშვნელოვანია გვახსოვდეს, რომ **System Call და Kernel ერთი და იგივე არ არის**. Kernel ოპერაციული სისტემის ბირთვია, რომელიც სისტემურ რესურსებს მართავს, ხოლო System Call არის ერთ-ერთი გზა, რომლითაც პროგრამა ამ ბირთვის ფუნქციებს მიმართავს. ასევე, System Call არ ნიშნავს, რომ ყოველი მოთხოვნა აუცილებლად დისკზე მონაცემების ფიზიკურ ჩაწერას იწვევს — ოპერაციულ სისტემას შეუძლია მონაცემები დროებით მეხსიერებაში შეინახოს და ჩაწერა მოგვიანებით შეასრულოს.

ამრიგად, System Call-ები ოპერაციულ სისტემასა და პროგრამებს შორის კონტროლირებად კავშირს უზრუნველყოფს. მათი დახმარებით პროგრამებს შეუძლიათ სისტემური რესურსების გამოყენება ისე, რომ აპარატურის მართვა და უსაფრთხოების მნიშვნელოვანი გადაწყვეტილებები ოპერაციული სისტემის კონტროლქვეშ დარჩეს.
