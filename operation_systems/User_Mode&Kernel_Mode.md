ოპერაციულ სისტემაში პროგრამებს ერთნაირი უფლებები არ აქვთ. ჩვეულებრივი პროგრამა არ უნდა მართავდეს კომპიუტერის აპარატურას ან ცვლიდეს სისტემის კრიტიკულ მონაცემებს შეზღუდვების გარეშე. ამის უზრუნველსაყოფად პროცესორი იყენებს მუშაობის სხვადასხვა პრივილეგირებულ რეჟიმს, რომელთაგან ყველაზე მნიშვნელოვანია **User Mode** და **Kernel Mode**.

**User Mode** არის რეჟიმი, რომელშიც ჩვეულებრივი პროგრამების უმეტესობა მუშაობს. მაგალითად, ბრაუზერი, მუსიკის პროგრამა და ტექსტური რედაქტორი ამ რეჟიმში ასრულებენ თავიანთ კოდს. მათ შეუძლიათ მონაცემების დამუშავება და პროგრამისთვის გამოყოფილი მეხსიერების გამოყენება, მაგრამ არ შეუძლიათ პირდაპირ შეასრულონ ყველა პრივილეგირებული ინსტრუქცია ან შეუზღუდავად მართონ აპარატურა. თუ პროგრამას დისკიდან ფაილის წაკითხვა ან ქსელური კავშირის გამოყენება სჭირდება, ის ოპერაციულ სისტემას შესაბამის მოთხოვნას უგზავნის.

**Kernel Mode** არის პრივილეგირებული რეჟიმი, რომელშიც Kernel-ის კოდი და, სისტემის არქიტექტურის მიხედვით, ზოგიერთი დაბალი დონის დრაივერი მუშაობს. ამ რეჟიმში კოდს მეტი წვდომა აქვს პროცესორისა და მეხსიერების მართვის შესაძლებლობებზე, ასევე აპარატურის რესურსებზე. ასეთი უფლებები აუცილებელია ოპერაციული სისტემის მუშაობისთვის, თუმცა შეცდომა Kernel Mode-ში შეიძლება მთელი სისტემის სტაბილურობას დაემუქროს.

წარმოვიდგინოთ, რომ ბრაუზერს სურს ფაილის გახსნა. ბრაუზერი მუშაობს User Mode-ში და ფაილზე წვდომისთვის მიმართავს ოპერაციულ სისტემას. მოთხოვნა გადაეცემა Kernel-ს სპეციალური მექანიზმის საშუალებით. Kernel ამოწმებს, აქვს თუ არა პროცესს შესაბამისი უფლება, და ორგანიზებას უწევს ფაილურ სისტემასა და დისკთან დაკავშირებულ ოპერაციას. საჭიროების შემთხვევაში პროცესორი გადადის Kernel Mode-ში, რათა სისტემურმა კოდმა პრივილეგირებული მოქმედება შეასრულოს. დასრულების შემდეგ შესრულება ბრუნდება User Mode-ში და ბრაუზერი აგრძელებს მუშაობას.

ამ მექანიზმის მთავარი მიზანია **Protection და Isolation** — პროგრამების ერთმანეთისგან და ოპერაციული სისტემის კრიტიკული ნაწილებისგან დაცვა. მაგალითად, თუ ჩვეულებრივი პროგრამა შეცდომის გამო ცდილობს მისთვის მიუწვდომელი მეხსიერების გამოყენებას, პროცესორმა და ოპერაციულმა სისტემამ შეიძლება ეს მოქმედება დაბლოკონ და პროგრამას შეცდომა დაუბრუნონ, ნაცვლად იმისა, რომ სხვა პროცესის მონაცემები დაზიანდეს.

უნდა განვასხვაოთ **User Mode** და მომხმარებლის ტიპი. Administrator-ად შესვლაც კი არ ნიშნავს, რომ ყველა პროგრამა ავტომატურად Kernel Mode-ში მუშაობს. Administrator-ს შეიძლება მეტი სისტემური უფლება ჰქონდეს, მაგრამ მისი ჩვეულებრივი პროგრამები მაინც User Mode-ში მუშაობენ. მომხმარებლის უფლებები განსაზღვრავს, რისი გაკეთების ნებართვა აქვს მას, ხოლო CPU-ის რეჟიმი განსაზღვრავს, რა ტიპის პრივილეგირებული ოპერაციების შესრულება შეუძლია მიმდინარე კოდს.

ამრიგად, User Mode უზრუნველყოფს პროგრამების შეზღუდულ და შედარებით უსაფრთხო გარემოში მუშაობას, ხოლო Kernel Mode ოპერაციულ სისტემას აძლევს საჭირო პრივილეგიებს კომპიუტერის რესურსების სამართავად. ამ ორი რეჟიმის გამიჯვნა თანამედროვე ოპერაციული სისტემების უსაფრთხოებისა და სტაბილურობის ერთ-ერთი საფუძველია.
